# Causora reviewed Matrix and Formula Trace v2

This additive contract supplements frozen frontend/API_CONTRACT.md; v1 requests and Golden snapshots remain unchanged. Authoritative response schema: backend/backend/contracts/causora.contract.v2.schema.json. TypeScript: frontend/lib/contracts-v2.ts plus shared trace body in contracts-v2-dev.ts. Runtime validator: frontend/lib/simulate-api.ts.

POST /api/simulate accepts the existing v1 SimulateRequest. Invalid requests and blocked gates return v1 error envelopes. Successful v2 responses contain simulation, deltas, selections, traces[scenarioId][optionId], executionContext; exactly three requested scenarios and D0/D1/D2 in each. The nine traces share one run/review/policy/release identity. Each carries five cost components, rounding audits, typed parameter provenance, probability/service denominators, nearest-rank cash P90, and 104 weekly rows from one realised trial (never an aggregate).

Reviewed transport requires HTTP headers x-causora-review-status=reviewed, x-causora-execution-mode=reviewed-release-gated, x-causora-trace-contract=causora.contract.v2. executionContext is mode=reviewed_release_gated, humanReviewStatus=reviewed, policyStatus=approved, contractReleaseStatus=released, decisionReady=true. Contract parameter source hashes identify original artifacts; reviewRecordSha256 identifies the independent human review record. Policy parameters bind policySha256; their sourceFile may be null because the policy artifact identity is carried by its hash and reference. Formal responses need no frontend development opt-in.

Development transport requires the exact UNREVIEWED_DEV_ONLY frontend and backend opt-ins, development headers, unreviewed simulation/data markers and decisionReady=false. A reviewed response containing unreviewed provenance or inconsistent run identities is rejected. No development transport can authorize a recommendation or approval. Reviewed simulation readiness does not create Boardroom outputs, user approval or supplier action; matching Boardroom and Brief integration are separate Day4 work.

The release record binds this document, backend schema, Pydantic model, TypeScript DTO and runtime validator hashes. The DTO imports contracts-v2-dev.ts for the numerical trace body; changing that dependency requires rerunning checks and explicitly reissuing the release record. The supplied pending release record is not a release.
